# Million Pound · 家庭宠物守护

为百万和英镑记录日常，识别吃喝、拆家、乱拉乱尿。Python + FastAPI + FFmpeg，配置网页与监控任务由同一服务运行，事件存入 SQLite。

## 在 Python 虚拟环境中启动

需要 Python 3.11+、FFmpeg（含 ffprobe 和 libx264）。所有 Python 命令均使用项目的 `.venv`，不向系统 Python 安装依赖。

```bash
cd ~/million-pound
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m million_pound init
.venv/bin/python -m million_pound serve
```

访问 `http://127.0.0.1:8097`，登录后默认显示活动时间线，导航中的「设置」和「事件」打开 `/settings` 对应区域。`init` 只运行一次，会显示随机初始密码，磁盘只保存密码哈希。默认暂停监控；在设置页配置视频源、测试连接、设置通知方式后，点击“开启守护”。8099 已由摄像头桥接占用，应用使用 8097。

当前开发设备已初始化、配置好视频源、模型与 Bark，后台服务及 linger 均已启用。直接登录即可使用，无需再次运行 `init`。

在网页的「设置 → 修改登录密码」输入当前密码、新密码并确认，即可立即修改，无需重启服务。成功后旧登录状态和旧图片签名失效，请用新密码重新登录。

也可以在本机修改登录密码：

```bash
.venv/bin/python -m million_pound password
```

密码长度为 11 到 256 个字符。命令行修改后重启应用生效；旧登录状态和旧图片签名一起失效。Cookie 有效期 12 小时，HTTPS 访问时启用 Secure。

## 小米摄像头接入

采用 [ha-xiaomi-camera 独立桥接服务](https://github.com/willjayyyy/ha-xiaomi-camera/blob/main/README.zh-CN.md#不用-home-assistant-也能跑)。需要 Docker，桥接主机与摄像头处于同一局域网。

1. 首次部署时复制 `.env.example` 为 `.env`，填写两个不同的随机长密码，并执行 `chmod 600 .env`。当前开发设备已配置，无需重复覆盖。
2. 执行 `sudo docker compose -f compose.camera.yaml up -d`。
3. 在 PC 直接打开 `http://127.0.0.1:8098`，用 `.env` 中的 `XIAOMI_CAMERA_WEB_PASSWORD` 登录。
4. 在桥接页面连接小米账号；小米登录完成后，将浏览器完整回调地址按页面提示粘贴回去。
5. 将摄像头的视频流地址填入应用设置。桥接为局域网模式，RTSP 地址需加入用户名 `xiaomi` 与 `.env` 中的 `XIAOMI_CAMERA_RTSP_PASSWORD`，形式为 `rtsp://xiaomi:密码@127.0.0.1:8554/camera_设备ID`。
6. 保存设置，点击“测试并查看截图”。默认使用原始视频流，应用支持 H.264/H.265 输入。

小米授权持久化在 `camera-data/`。不要把 8098 或 8554 映射到公网域名；公网只代理 8097 的应用。桥接镜像版本采用上游 `latest`，升级后需重新测试取流。

## 监控行为

- 按北京时间执行每天的监控时段，支持跨午夜；不填时段或开始与结束相同表示全天。
- 监控开启后保持同一条视频连接持续录像，按片段交给独立的分析任务；模型处理和复核期间继续采集。默认每段六十秒，每秒抽两帧、六倍速，生成约十秒、共一百二十帧的视频，每分钟调用一次 `d3`。页面可调整片段长度、抽帧率和倍速，旧版的采样间隔已移除。
- 原速录像编码为 H.264 并将首帧时间对齐到零，避免 RTSP 等待关键帧导致短片开头空白或无截图；录像保留原始分辨率。
- `d3` 的 `/v1/systemone` 每段只请求一次，同时返回两只宠物的入镜、主要活动和吃喝、拆家、乱拉乱尿三类预警。请求包含加速视频和本段原始截图；入镜仅按模型选项判断，不设分数门槛，选择入镜就采用活动结果。两只均未入镜时忽略活动和预警。预警概率达到 0.7 进入候选；接口字段缺失或无效会明确失败，不当作“没有事件”或“未入镜”。
- 候选截图取自原速录像的 10%、50%、90% 位置；事件时间显示本段原视频采样开始时间，截图标注原视频内的秒数。
- 仅有上述特殊事件候选时，才调用一次 `swift-1.5` 的 `/v1/chat/completions`，同段多个候选一并复核。原速六十秒录像均匀抽取二十帧，拼成一张四列五行的大图，从左到右、从上到下按时间排序，作为唯一图片提交；正常活动不调用。复核拼图仅临时生成，事件页保留原速录像的三张独立截图。最短复核间隔默认零，每段候选均复核；可在页面设为正数，复核开始时间持久化，失败及重启也不会绕过该间隔。
- 因间隔限制未复核的候选标为“未复核”，不排队、不发送通知；之后新采样仍有该行为时再复核。原片不长期保存。
- 只有复核明确确认的事件才按类型发送 Bark；默认吃喝只记录、拆家及乱拉乱尿通知，可在网页修改。
- 同类型、同宠物在五分钟内合并通知。通知失败会标明；发送中断时标为“结果待确认”，不会自动重试原通知。
- 保存配置或暂停守护会停止当前连续录像，未完成判断的记录会标记中断；结尾不足一段的片段会尽可能保留截图，不补猜活动或发送通知。
- 待分析原片最多缓存三十段或 256MiB；超出时仍保留该时段截图，明确标为“积压未判断”。磁盘可用空间不足 1GB 时暂停采集，避免占满磁盘。
- HTTPX 与 FFmpeg 不使用系统代理，保证局域网模型和摄像头直连。模型服务地址可填写根地址或带 `/v1` 的地址。

连续录像使用 [FFmpeg segment](https://ffmpeg.org/ffmpeg-formats.html#segment_002c-stream_005fsegment_002c-ssegment)，抽帧使用 [fps 过滤器](https://ffmpeg.org/ffmpeg-filters.html#fps-1)。抽帧与分段判断仍可能遗漏短暂行为，实际识别效果需用家中宠物画面调整参数，不保证零误报或漏报。

## 带图片的活动时间线

网站首页和登录后默认显示活动时间线，也可访问 `http://127.0.0.1:8097/activities`。使用原有登录密码。

- 百万固定在中央时间线左侧，英镑在右侧，展示睡觉、吃喝、走动、玩耍和其他活动，不再展示“未知”。未达到确认条件的活动保留原有字体和虚线区分，名称不加“疑似”，包括顶部状态和详情；模型选择不确定时，取分数最高的真实活动作为候选，排除不确定、未知和未入镜选项。睡觉与休息、吃饭与喝水分别使用统一名称。
- 连续的同类活动合并为一段括号形线段，起止位置按真实时间映射到中央的连续竖轴；中央下拉框可将每格切换为 5、15、30 或 60 分钟，默认 15 分钟，时间刻度、活动区间、图片和折叠列表同步调整。左右两侧使用相同比例，持续越久线段越长；空档保留，同一时段的活动允许重叠。筛选区只保留日期及前后切换，两只宠物同时展示。
- 活动名称和持续时长显示在线段旁，点击名称或线段可查看原始观察、置信度和照片，支持切换画面或拖动进度条。未入镜、入镜不确定、失败和无可用候选的时段隐藏并留下真实空档。旧版曾因入镜分数门槛漏存活动答案：这类记录若模型选择入镜，且两侧仍是睡觉、采集连续、缺口不超过一分钟，则在展示时连接睡觉，详情保留缺口的原始未确认观察；不改写历史判断。同一活动的确认与待确认连续观察合并，只要这一段有确认记录，就按确认状态展示；整段都未确认时保留原有字体和虚线区分。翻看历史时继续自动更新，打开详情时保留当前画面，关闭后展示更新结果。
- 每格内的名称错开排列，用细引线对应真实区间；桌面单侧超过三段时显示两段名称和余量入口，展开可查看该格全部活动并点开照片。手机上给图片留出上半格，名称最多两行，拥挤时显示一段名称和余量入口。折叠不隐藏任何区间线段，也不改变时间比例。
- 左右每个格子最多各显示一张确认入镜截图，按实际截图采集时间归格，不跨格借图。选图优先级为乱拉乱尿、拆家、吃喝、玩耍、走动、睡觉，同类选较新画面。乱拉乱尿和拆家来自同段录像的已确认预警，并分别核对宠物归属；未入镜、身份未确认、没有截图或图片加载失败时留空。缩略图保持静态，点击后播放同段传给 d3 的加速 MP4，无声循环，支持暂停和拖动进度；切换观察或关闭详情时停止并卸载视频。旧记录没有视频或视频加载失败时显示静态原图和原始判断。

格内图片与优先级更新已通过 49 项后端、27 项前端及桌面、390px、320px 浏览器检查，另核对了 820px 和 640px 布局；包含跨格截图、预警分页与宠物归属、失效图片隐藏和点图查看对应原图。
- 吃东西与喝水统一判断为“吃喝”，模型不再区分水盆和饭盆；历史 `drinking`、`eating` 记录在页面中合并展示，不改写旧数据。
- 首次确认普通活动要求 d3 分数达到 0.6，睡觉要求 0.8。确认后，只要后续活动仍为同一状态，便继续延续，不因单次低分切换。模型选择不确定时，最高分的非未知活动若仍与已确认状态相同，也延续该状态；原始选择、候选分数和延续原因保留在详情。日常活动不调用 swift-1.5，也不直接触发通知。
- 每段仍独立核对入镜；未入镜、身份不清或判断失败的时段在图上留下空档。每只宠物保留不到一分钟的最近状态作为参考，重新通过入镜确认且候选仍相同时可继续原状态；候选改变或空档达到一分钟时按新状态首次确认规则处理。状态参考从数据库读取，实时分析与历史重算共用规则，刷新和翻页不改变结果。
- 时间连续性允许切片末帧产生最多 100 毫秒的重叠，避免把 FFmpeg 的毫秒偏差当作采集中断；新采样与历史重算共用这一判断。切换日期时清除已加载的记录，再读取所选日期。
- 入镜检查使用实际外观：百万浅黄色/奶油色短毛、体型大；英镑深色长毛、长尾蓬松。只认真实身体结构，排除另一只宠物、靠枕、垫子、玩具、鞋子和阴影。
- 入镜选择 `present` 就采用该宠物的活动分类，选择 `absent` 就记录“未入镜”，选择 `uncertain` 则记录“判断不清”；入镜分数仅供详情查看，不参与判断。旧记录不再受原来的入镜分数标记限制。未入镜或入镜不确定的记录保留在后台，在时间线上隐藏；入镜和活动答案相矛盾时仍保留不确定。
- 睡觉与休息共用一个活动选项，d3 不再区分两者：趴卧、蜷卧、闭眼或安静待着都按睡觉判断，首次确认分数仍为 0.8。入镜和活动答案相互矛盾时保留“判断不清”。这些分数是模型输出，不等于实际准确率。
- 每段在原视频中间位置保存一张截图，标明录像起止时间和截图时间；点击图片查看原图。预警复核需要时再补充前后两张截图。
- 网页时间按采集端估算，可能有几秒传输和编码延迟；截图同时带有摄像头自身时钟，可据此核对。
- 按北京时间日期查看，从新到旧展示；每次最多读取 1000 条并自动连续加载更早记录。页面默认每五秒自动更新所选日期，翻看历史也不停止，无需手动刷新；返回页面时立即更新，请求失败后继续重试。格内缩略图按需加载，打开详情可查看原图。

## Bark 与公网截图

在配置页填写 Bark 地址。可以直接粘贴 Bark 示例中的完整 URL，应用会提取设备密钥并保留 `group`、`ttl` 等查询选项，再替换通知标题与正文。支持常规 `https://服务器/设备密钥/标题/正文` 格式。

按 [Bark 官方参数](https://github.com/Finb/Bark/blob/master/docs/en-us/params.md#image)，图片需要手机可访问的 URL：

1. 将 `https://pets.example.com` 的 HTTPS 反向代理指向 `127.0.0.1:8097`，参考 `deploy/nginx-location.conf`。转发 Host 和 X-Forwarded-Proto。
2. 在网页“公网访问地址”填写该 HTTPS 地址；它也用于登录和设置请求的来源校验，代理未保留原始地址且漏填时会报“请求来源无效”。首次无法从公网登录时，先通过局域网页面填写，或修改 `config.json` 的 `public_url` 后重启服务。留空时只发文字，事件里会明确标记。
3. 通知使用 `/shared/文件名?expires=...&sig=...`，一小时内无需登录即可读取指定截图；篡改文件名或到期会拒绝访问。普通事件与截图接口始终需要登录。
4. 点击“发送测试通知”可测试文字通道；真实确认事件用于最终验证手机图片展示。

## 后台运行

仓库提供当前设备的用户级 systemd 服务；换目录时修改其中的绝对路径。

```bash
mkdir -p ~/.config/systemd/user
cp deploy/million-pound.service ~/.config/systemd/user/
systemctl --user daemon-reload
systemctl --user enable --now million-pound
systemctl --user status million-pound
tail -n 50 data/server.log
```

若需要退出 SSH 后继续运行及开机启动，由管理员执行一次 `sudo loginctl enable-linger "$USER"`。

只运行一个应用实例、一个 worker，避免重复采样与推送。更改本地配置文件或 CLI 修改密码后，执行 `systemctl --user restart million-pound`；网页修改设置即时生效。

## 本地数据与检查
